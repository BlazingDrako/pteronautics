Aerospace engineering, from first principles to a whole vehicle.

Pteronautics is a family of aerospace programs. Atlas teaches the physics with a live visual for every concept. Works puts the same validated solvers to work designing whole vehicles. Loom models the whole system in SysML, from requirements to the parts that meet them.

Three programs

Learn it in Atlas. Design it in Works. Model it in Loom.

Atlas and Works run the same solvers, checked against textbooks, published data and reference codes: Atlas opens each one up so you can see how it behaves, and Works couples them around a vehicle so a single edit flows through the whole design. Loom holds the system around them: what it must do, how it is broken down, and how each requirement is met and verified.

Pteronautics Atlasready

Aerospace engineering you can see.

Fourteen interactive tools across aerodynamics, propulsion, structures, flight and orbits. Every result comes with a picture: watch pressure build on a wing, the boundary layer separate, shocks form and engines breathe.

  • An XFOIL-class airfoil solver, vortex-lattice wings, a GPU flow sandbox
  • Shocks, nozzles, jet and rocket engines, heat transfer, rotors
  • Frames and FEA, flight performance and stability, orbits and GNC

Pteronautics Worksfirst slice

Design the whole vehicle. Every analysis follows.

A design program built around a vehicle. Change the wing and the aerodynamics, mass and balance, stability, performance and requirements recompute together, through a coupling graph that shows what is current and what is stale.

  • Systems tree, a 3D view and a to-scale top view with lift and the CG
  • Fidelity you choose: lifting line, vortex lattice, viscous section polars
  • Requirements with live margins; vehicles saved as plain .json

Pteronautics Loomready

Every requirement, woven through to the part that meets it.

Model-based systems engineering in SysML. Requirements, functions, logical and physical architecture and verification live in one model, traced end to end, and every diagram is a view of it.

  • Nine SysML diagram kinds, with tool palettes and smart connections
  • Saved as SysML v2 text, ready for git; equations and requirement checks live
  • Imports Cameo models; ReqIF, Excel and the SysML v2 API; installs and works offline

Pteronautics Works

One edit. Every analysis follows.

Each analysis in Works declares what it reads from the vehicle and which results it needs. An edit marks only what depends on it as stale, and the coupling graph reruns those, in order. These sliders drive the real graph.

Pteronautics Loom

The whole system, in one model.

Every diagram in Loom is a view of one SysML model, organized in four layers: requirements, functions, logical architecture and physical parts. Rename a block on one diagram and it changes everywhere; trace a requirement from the stakeholder need to the part that satisfies it and the test that verifies it.

Real SysML, v1 and v2Block, internal block, requirement, activity, state machine, sequence, use case, package and parametric diagrams, in SysML or SysML v2 words.
Traced and checked liveThe Systems V shows what is satisfied, verified and passed; equations solve as you type and requirement checks pass or fail against the design.
Plain text, ready for gitA project is a folder of SysML v2 text files you can diff, review and merge.
Works with your toolsImport Cameo and MagicDraw models; exchange requirements as ReqIF or Excel; talk to SysML v2 API servers; print documents to PDF.
